y² ≡ x³ + 7 (mod 17)

Theory: the ideas behind the app
1. The toy curve y² ≡ x³ + 7 (mod 17). It is the same equation Ethereum uses (secp256k1), but modulo 17 instead of a 256-bit prime, so every step can be checked by hand. It has 17 points plus a special point at infinity, O.
2. The base point G = (1, 5). A public starting point that everyone knows. It is on the curve because 5² = 25 ≡ 8 and 1³ + 7 = 8. If we keep adding G to itself, after 9 steps we are back at O: G has order 9.
3. Adding two points. λ = (y₂ − y₁)/(x₂ − x₁) for two different points, λ = 3x₁²/(2y₁) to double a point. Then x₃ = λ² − x₁ − x₂ and y₃ = λ(x₁ − x₃) − y₁, all mod 17. Dividing mod 17 means multiplying by the inverse: 1/10 ≡ 12, because 10·12 = 120 = 7·17 + 1.
4. Public key Q = k·G. We add G to itself k times. Double-and-add is the faster way: it doubles at every bit of k and adds G only when the bit is 1.
5. The point at infinity O. It works like zero: P + O = P. We get it when we add a point to its mirror image (x, −y). Since 9G = O, keys repeat every 9 steps: 15G is the same as 6G.
6. Why it is a one-way function. Going from k to Q is fast. Going back from Q to k is very hard on the real curve (around 2¹²⁸ operations). On our toy curve we just try k = 1, 2, 3… and find it in at most 9 tries.
7. Why there is no drawn curve mod 17. Modulo 17 the curve is only a set of separate points, so there is nothing to draw between them. The real-number picture in the visualiser is just an analogy to see the geometry.

What the experiments show

      
    
        
  • The toy curve is tiny. It has 18 points (17 + O) and G = (1,5) only reaches 9 of them. Key 9 gives O and keys repeat every 9, so there are just 8 usable private keys.
    • 
        
  • Frequencies. Going through k = 1…8, every point appears exactly once. The coordinates instead are not uniform over 0…16: only 4 values of x appear (each twice, because a point and its mirror (x, −y) share the same x) and 8 values of y.
    • 
        
  • χ² test. With k = 1…9 the test is not reliable: we expect less than one observation per value, and the χ² test needs at least about 5. It would even say "uniform" for x, although 13 of the 17 values never appear. Also, k = 1, 2, 3… is not a random sample, so the counts are fixed in advance. That is why we added the test with random keys.
    • 
        
  • Bits. The top bit is almost always 0 just because numbers from 0 to 16 are written on 5 bits.
    • 
        
  • Correlation. Pearson's r is low, but r only sees straight-line relations. Q still depends completely on k (it repeats every 9 steps and has the mirror symmetry).
    • 
        
  • Avalanche. The share of changed bits is close to 0.5 only because the outputs are so few. What really separates ECC from SHA-256 is that the change is predictable: Q′ = Q ± 2ⁱ·G.

For a public key what matters is that it is fast to compute, always the same for the same k, and impossible to reverse on a big curve. Avalanche and collision resistance are hash properties. In fact Ethereum applies a hash (Keccak-256) to Q afterwards, to get the address.

    


    

      
Why these statistical tools (and their limits)

      
Uniformity. Each key from 1 to n−1 gives a different point, so going through all keys we see every point exactly once. Uniformity over the points is therefore guaranteed, we don't need a test to prove it. A test makes sense only when k is chosen at random.

      
χ² test. It compares what we observe with what we would expect if the values were uniform: χ² = Σ (observed − expected)² / expected. If χ² is above the critical value, we reject uniformity at the 5% level. Two things must be true for the test to work: we must compare with the right list of possible values (G = (1,5) can only produce x = 1, 2, 5, 12), and we need at least about 5 expected observations per value.

      
Entropy. It measures how spread out the values are, in bits (3 bits = 8 equally likely outcomes). Here H(x) = 2 bits and H(y) = 3 bits, because x has only 4 values. High entropy does not mean the function is hard to reverse.

      
Pearson correlation. It only detects straight-line relations. Q depends completely on k, but in a "circular" way (mod n), so r stays low.

      
Avalanche. A good hash changes about half of the output bits when one input bit changes, in an unpredictable way. Here the change is always Q ± 2ⁱ·G, so it is fully predictable.

      
Other base points. The order of G decides how many public keys exist: with order 18, e.g. G = (15,13), we reach all 17 points; with order 2 or 3 only 1 or 2. Real curves use a base point with a huge order.
